# avec

avec is a freestanding Apache Arrow columnar substrate: an in-memory columnar
vector library (`avec-arrow`) plus Parquet persistence kernels (`avec-parquet`),
both `no_std` + `alloc` with zero external dependencies. Buffers are 64-byte
aligned at allocation. The scan kernels' compiled inner-loop bodies are
branch-free — loop latches, dispatch, and bounds checks are control flow,
itemized per symbol by the branch audit gate (`make branch-audit`: 3/9 loop
kernels measure BODY 0/0; 71 conditionals itemized across 9 kernels, unaccounted
0). Arrays cross language boundaries through the Apache Arrow C Data Interface
as zero-copy `ArrowArray` / `ArrowSchema` pairs with atomic release-swap
single-release ownership.

The repo is ontology-driven: the Arrow layout ground truth (format codes, buffer
counts, slot widths), the C header ABI, and even the release version string are
generated by [ggen](https://github.com/seanchatmangpt/ggen) from an RDF ontology. Layout dispatch
(`crates/avec-arrow/src/generated_layout.rs`), format-code macros
(`include/avec_format_codes.h`), the C Data Interface header (`include/avec_c_data.h`),
and the version constant (`crates/avec-arrow/src/generated_version.rs`) are projections;
the kernels in `crates/avec-arrow/src/` are the hand-written irreducible residue.
Every quality claim in this README is backed by a command in the Receipts section.

`Varlen` / `ViewVec` vectors, and the C Data Interface ABI in `c_abi.rs`.

## Generated files: ontology in, code out

`ggen sync run` projects four generated surfaces from the avec-pack ontology:

```console
$ ggen sync run          # renders:
#   include/avec_c_data.h
#   include/avec_format_codes.h
#   crates/avec-arrow/src/generated_layout.rs
#   crates/avec-arrow/src/generated_version.rs
```

The pack is pinned in `ggen.toml` (`avec-pack = { path = "../ggen-marketplace/packs/avec-pack" }`)
and content-hashed in `ggen.lock` (blake3, 2 subjects). All four files are marked
`do not edit` in their headers; hand edits are overwritten by the next sync. Gate 0
re-runs the sync twice and requires byte-identical output, then compiles the C header
freestanding (`cc -std=c99 -ffreestanding -Wall -Wextra -pedantic`).

## Quickstart

```console
$ make test        # cargo test --workspace
$ make gates       # gate0 -> gate1 -> gate2 -> gate3, fail-closed
$ cargo run --release -p bench   # CTQ-1 throughput + alloc count, single command
$ make branch-audit  # compiled-machine-code branch budget, per symbol
```

Prerequisites: Rust stable (edition 2021), `python3` with `pyarrow` (Gate 3 imports the
exported batch through `pa.Array._import_from_c`; 23.0.1 used for the receipts below),
`ggen` on `PATH` (Gate 0), and `xcrun llvm-objdump` (Gate 1). No step needs network
access after the first `cargo build`.

## Scope notes (read before quoting any number)

- **Branch scoping.** No kernel is claimed "zero branches" unqualified. The audited
  claim: inner-loop bodies branch-free; loop latches, dispatch, bounds checks, and
  panic/fail paths are control flow, itemized. `make branch-audit` scans the TRUE
  callee extents of 9 loop kernels plus 12 `audit_*` wrapper shims in
  `target/audit/libavec_audit.dylib`. The `rle`/`packing` kernel sites listed in
  `docs/BRANCH_REGISTER.md` R3 are outside the audited symbol set (the audit crate
  wraps the parquet `unpack` family only). Register of record:
  `docs/BRANCH_REGISTER.md`.
- **Parquet scoping.** `avec-parquet` provides RLE/bit-packed kernels plus a minimal
  DataPageV2-style page framing (`crates/avec-parquet/src/page.rs`). It is NOT the
  full Parquet format: no row groups, no column/file metadata, no footer magic, no
  repetition/definition levels (V2 level byte lengths must be zero), no compression
  (`is_compressed` must be false). Scope quote from `page.rs`: "this is a *minimal
  DataPageV2-style framing*, NOT the full Parquet format."
- **BEAM membrane latency: FAIL as measured.** `docs/BEAM_LATENCY.md` (source of
  record) ran the mandated instrument under concurrent lane load (loadavg 14.14):
  scheduler-impact differential 7985.791 us and absolute loaded timer-drift max
  11128.208 us against the 50 us gate — impact FAIL, absolute FAIL. A second run
  flipped the differential's sign (impact "PASS" on a negative differential; absolute
  still FAIL), so at that load the differential is noise-bound. The stable finding:
  the idle 1 ms timer floor alone (3.1-11.2 ms) exceeds the gate by 60x-220x before
  any NIF churn — this instrument on this host cannot resolve the 50 us CTQ either
  way. No threshold was adjusted. No BEAM/AtomVM runtime test exists in this repo.
- **Mutation court.** `docs/mutation-court-backlog.txt` lists 114 mutation sites as a
  plain list — no header, no verdict in the file. No pass/fail court receipt exists
  in the repository; closure lanes are in flight. Until one lands, CTQ-3 stays
  NO-RECEIPT (see `docs/DFLSS_CHARTER.md` section 2).
- **wasm footprint.** `scripts/footprint.sh` exists and `docs/wasm-footprint.txt`
  records the combined stripped artifact at 10123 bytes (TARGET <= 100 KiB and USL
  <= 250 KiB, both PASS) from the harness that supplies panic handler + allocator
  glue in a throwaway crate. An earlier run of the script's prior revision was
  BLOCKED exit 101 (`docs/RECEIPTS.md` receipt 7). The script's mtime postdates the
  recorded artifact, so the PASS verdict is receipt-cited, not re-run this session.
- CTQ-4 target of record is 250 KiB stripped wasm32-wasip1 (`ontology/avec.ttl`,
  av:ctq4). See `docs/DFLSS_CHARTER.md` for the full CTQ register and verification
  ladder.
