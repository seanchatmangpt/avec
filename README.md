# avec

avec is a freestanding, branchless Apache Arrow columnar substrate: an in-memory columnar
vector library (`avec-arrow`) plus branchless Parquet persistence kernels (`avec-parquet`),
both `no_std` + `alloc` with zero external dependencies. Buffers are 64-byte aligned at
allocation, scan kernels compile to zero conditional branches (proved on the compiled
machine code, not asserted), and arrays cross language boundaries through the Apache Arrow
C Data Interface as zero-copy `ArrowArray` / `ArrowSchema` pairs with atomic
release-swap single-release ownership.

The repo is ontology-driven: the Arrow layout ground truth (format codes, buffer counts,
slot widths), the C header ABI, and even the release version string are generated by
[ggen](https://github.com/seanchatmangpt/ggen) from an RDF ontology. Layout dispatch
(`crates/avec-arrow/src/generated_layout.rs`), format-code macros
(`include/avec_format_codes.h`), the C Data Interface header (`include/avec_c_data.h`),
and the version constant (`crates/avec-arrow/src/generated_version.rs`) are projections;
the kernels in `crates/avec-arrow/src/` are the hand-written irreducible residue.
Every quality claim in this README is backed by a command in the Receipts section.

## Repository layout

| path | contents |
|---|---|
| `crates/avec-arrow` | in-memory substrate (`no_std`, zero deps): aligned `Buf`, SWAR |
| `crates/avec-parquet` | Parquet kernels (`no_std`, zero deps): 1/2/4/8-bit unpack, RLE |
| `crates/avec-ffi` | C-ABI cdylib membrane for Gate 3 wire parity |
| `crates/avec-beam` | BEAM/AtomVM NIF membrane (erl_nif ABI in Rust; in progress) |
| `crates/audit` | cdylib forcing kernels into the artifact for the branch audit |
| `crates/bench` | Gate 2 harness: mask throughput + allocation interception |
| `include/` | generated C headers: `avec_c_data.h`, `avec_format_codes.h` |
| `ontology/avec.ttl` | project graph: version, release date, CTQ facts (source of truth) |
| `gen-templates/` | ggen templates (`version_rs.tmpl`) |
| `scripts/` | gates: `branch_audit.py`, `gate3_cdata.py` (+ legacy `branch_audit.sh`) |
| `generated/` | ggen projection metadata (`subject-count.txt`) |
| `Makefile` | gate surface: `test gate0 gate1 gate2 gate3 gates lint publish-check` |

The `avec-arrow` table row names the core types: LSB-first `Bitmap`, `Primitive` /
`Varlen` / `ViewVec` vectors, and the C Data Interface ABI in `c_abi.rs`.

## Generated files: ontology in, code out

`ggen sync run` projects four generated surfaces from the avec-pack ontology:

```console
$ ggen sync run          # renders:
#   include/avec_c_data.h
#   include/avec_format_codes.h
#   crates/avec-arrow/src/generated_layout.rs
#   crates/avec-arrow/src/generated_version.rs
```

The pack is pinned in `ggen.toml` (`avec-pack = { path = "../ggen-marketplace/packs/avec-pack" }`)
and content-hashed in `ggen.lock` (blake3, 2 subjects). All four files are marked
`do not edit` in their headers; hand edits are overwritten by the next sync. Gate 0
re-runs the sync twice and requires byte-identical output, then compiles the C header
freestanding (`cc -std=c99 -ffreestanding -Wall -Wextra -pedantic`).

## Quickstart

```console
$ make test        # cargo test --workspace
$ make gates       # gate0 -> gate1 -> gate2 -> gate3, fail-closed
$ cargo run --release -p bench   # CTQ-1 throughput + alloc count, single command
```

Prerequisites: Rust stable (edition 2021), `python3` with `pyarrow` (Gate 3 imports the
exported batch through `pa.Array._import_from_c`; 23.0.1 used for the receipts below),
`ggen` on `PATH` (Gate 0), and `xcrun llvm-objdump` (Gate 1). No step needs network
access after the first `cargo build`.

## Scope notes

- `crates/avec-beam` is a work in progress: the erl_nif ABI is transcribed and the crate
  compiles under `cargo test --workspace`, but no BEAM/AtomVM runtime test exists here yet.
- CTQ-4 (wasm footprint) has a target in `ontology/avec.ttl` but no measurement harness in
  the repository; CTQ-3 (mutation court) has `cargo-mutants` installed and a pointer in
  `Makefile` but no court receipt in the repository. See `docs/DFLSS_CHARTER.md` for the
  full CTQ register and verification ladder.
