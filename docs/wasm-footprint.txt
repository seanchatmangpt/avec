## Method (public-API closure)

Both crates are #![no_std] + alloc libs whose panic handler and global
allocator are supplied by consumers, so a direct `cargo rustc
--crate-type cdylib` cannot link. The script mints a throwaway harness
crate in /tmp (never committed) that supplies the glue (panic handler +
a never-called GlobalAlloc, ~0 bytes) and a GENERATED keep-alive module
referencing every public function path found in nightly rustdoc JSON
(`black_box(path as usize)` inside an exported pub fn). Generic-type
methods are instantiated over the concrete candidates present in the
crates' own trait impls (e.g. impl Offset for i32/i64). Default GC then
retains exactly the public-API closure over that instantiation set.

This measures what a maximal consumer of the full public API links.
It is neither padded by dead private code nor thinned by dropping
generics. LTO = thin, codegen-units = 1 (mirrors [profile.release]).

Failed mechanisms recorded so they are not retried: (a) naive harness
cdylib with pub re-exports -> 213 bytes stripped (foreign re-exports are
not cdylib exports, dep members lazy-pulled); (b) whole-archive'd rlib +
--no-gc-sections -> 191 KB wasm of which 99.8% name/linking custom
section, code section 4 bytes (wasm-ld strips unreachable code even
under --no-gc-sections); (c) --export-all -> link failure (undefined
core/alloc symbols under LTO + whole-archive).
